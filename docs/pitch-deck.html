5 How it works

A pipeline, not a search box

1Goal textword + character TF-IDF → SVD, 128 dimensions
2Profilernoisy-OR mastery × recency decay
3Gap enginetarget − mastery, weighted by importance
4Hybrid rankersix signals, attribution retained
5Plannergreedy submodular → topological sort → milestones
Mastery saturates. Two courses each teaching Python at 0.5 don't make an expert — they overlap. Noisy-OR gives diminishing returns and can't exceed 1.0.
Knowledge decays. A course finished three years ago counts for less than one finished last month — but never for nothing.

Under that conversation is a pipeline, not a search box.

The goal text, the courses, the skills and the career roles all get embedded into one shared space, so any two can be compared directly.

Your history becomes a mastery vector. And the modelling choice that matters is that mastery saturates — it combines by noisy-OR, so two courses each teaching Python at 0.5 don't make you an expert, because they overlap. That's what stops it recommending Python once you clearly know Python.

Subtract mastery from what the goal requires, weight by importance, and "personalised" stops being a slogan — it's arithmetic you can inspect.

6 AI / ML implementation

Six signals, because each one fails alone

Ranking weights

Gap coverage0.38
Semantic0.18
Item-item CF0.14
Level fit0.12
Quality prior0.10
Modality0.08
  • Coverage ignores quality · semantics ignore what you know · collaborative filtering cold-starts · level-fit ignores the goal
  • Path selection is budgeted maximum coverage, and the objective is submodular — greedy carries the (1 − 1/e) guarantee
  • After every pick it simulates the mastery you'd gain and recomputes the gap — which is what stops four overlapping intro-ML courses

The ranker combines six independent signals, because every one of them fails on its own. Coverage ignores quality. Semantics ignore what you already know. Collaborative filtering cold-starts and just echoes what's popular. Level-fit ignores the goal entirely.

Choosing the path itself is a budgeted maximum-coverage problem, and the objective is submodular — each extra course on a topic adds less than the last. So greedy selection carries the standard one-minus-one-over-e approximation guarantee and runs in milliseconds.

After each pick we simulate the mastery you'd actually gain and recompute the remaining gap. That's the thing that stops it handing you four overlapping intro-to-ML courses.

Q Anticipated questions · keep this one to yourselves

What they'll probe, and the honest answer

Isn't this just a ChatGPT wrapper?No — and it runs with no API key at all. The ranking, ordering and explanations are deterministic local models. Claude only rewrites wording, and never chooses or orders anything.
Your interaction data is synthetic — isn't the CF meaningless?Fair. It's a real item-item CF model over real co-occurrence structure, but the co-occurrences are simulated from a fixed seed. It carries 14% of the ranking weight; the other 86% uses no simulated data. With real enrolment logs it improves immediately.
Why LSA and not a neural sentence encoder?A deliberate trade. A transformer embeds better but costs a ~500 MB download and version-dependent output. LSA fits in under a second, is byte-reproducible, and runs offline — so any judge can clone and run it. At 238 items it doesn't change the ranking; at 100× the catalog, a neural encoder would win.
How do you know the recommendations are actually good?We measured it — slide 9. 60 synthetic learners, four strategies, equal hour budget: 2.5× the achievable readiness gain of the best baseline, 100% prerequisite validity against 43%. Run it yourself: python -m app.ml.evaluate.
Synthetic learners aren't real learners.Correct, and we say so in the report. Gain is simulated with the same mastery model the planner uses, so it measures selection and sequencing under a fixed learning model — it can't tell you the learning model is right. Only a trial with real learners does that. The relative comparison survives, because every strategy is scored by the same instrument.
Can it recommend a course that doesn't exist?No. It selects from a fixed curated catalog — there is no generative step anywhere in selection, ordering or scheduling. That's the standard failure of LLM-based path generators and it's structurally impossible here.
Where do your 116 skills come from?Hand-authored — and we checked them against ESCO, the EU's public occupational standard, to find out how much of our space a standard actually covers. 10 of 116 have an unambiguous ESCO concept. ESCO classifies occupational competences and has none for PyTorch, RAG, Kubernetes or React. That is the real state of public skill taxonomies for fast-moving technical work, and it is why the prerequisite edges had to be authored: they exist in no public dataset.
Only 10? That sounds like the mapping failed.The permissive versions "succeeded" — 93 of 116 — by matching "Bash & Shell" to airport terminal standards and "UX Research" to perform interviews. We kept tightening until every surviving match was one we'd defend out loud, which meant requiring the two names to be the same name. A small correct answer beats a large plausible one.
How does it scale to 100,000 courses?The ranker is vectorised and the graph algorithms are near-linear, so planning holds. Retrieval would need an ANN index instead of a dense scan — that's the one change.
Where does the catalog come from / would you scrape?Curated deliberately: prerequisite edges exist in no public course dataset and they're the backbone here. An institution plugs in its own catalog — we proved that with a medicine catalog and zero code changes.
Completing a course ≠ learning it.Agreed, and that's exactly why assessments are first-class catalog items and why a score modulates the credit. We infer learning; we're explicit that we don't measure it.
What would you build next?Now that the evaluation harness exists, tune the six ranking weights against it instead of hand-setting them — the objective is already defined. Then real enrolment data, and persistence beyond in-memory sessions.
Anything you'd have done differently?Built the evaluation harness first. We wrote 188 tests before we ever measured whether the output was good, and the harness found a real defect within minutes of existing.
